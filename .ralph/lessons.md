# Lessons
Patterns and mistakes. Review at start of each iteration.
---
- The old site (~/src/actor-kit/website/src/pages/index.astro) used a CUSTOM StarlightPage, not the default splash template. The custom page has hand-crafted HTML/CSS for hero, features, and tabbed code.
- Starlight's built-in splash template uses CardGrid which looks generic. For a compelling homepage, use a custom page component.
- The v1 site's orange color scheme (#f6821f) with dark background looks professional. Keep the same palette.
- Tabbed code examples are the killer feature of the v1 homepage — they show the full stack in one glance.
- The docs dev server runs at http://localhost:4321
- Use mcp__claude-in-chrome tools to take screenshots and interact with the page
- Function parameter contravariance (strict mode) prevents typed role predicates from being assignable to ActorDef's bivariant interface. Use a type guard (`isActorDef`) instead of `as` cast to bridge the gap in createActorClass.
- `@actor-kit/worker/testing` entrypoint avoids cloudflare:workers — use it for unit-testable exports like defineActor.
- New files default to tabs; biome wants spaces. Run `biome check --fix` on new files before committing.
- Integration tests need `pnpm build` in packages/worker before they pick up new exports (wrangler resolves from dist/).
- Guard type change from `(state) => boolean` to `(state, payload, ctx) => boolean` is backward compatible: TS allows fewer-param functions to be assigned to more-param types, and JS ignores extra args. But ActorMessageSlot/RoutableMessage bivariant method signatures MUST also be updated — a 3-param function is NOT assignable to a 1-param function type (even with bivariance).
- When detecting flat vs role-nested messages, check ALL entries for both `schema` AND `handler` properties. Checking only the first entry or only `schema` creates false positives when role names collide with MessageDef property names.
- When removing a feature that spans multiple packages with dual actor.ts files (actor-kit + worker), remember to update BOTH copies — and also the test harness packages (packages/test, packages/actor-kit/src/test). The codex review catches stale references in test files.
- CREATE_TABLES_SQL must be kept in sync with persistOutbox() — unused columns in the schema are a migration hazard flagged by codex.
- Removing `async`/`await` from handler types is NOT sufficient to prevent async at runtime. An `async` function is assignable to `(...) => unknown` (and even `(...) => TState` through bivariant method signatures). Always add `instanceof Promise` runtime guards when removing async support — this is defense-in-depth against JS consumers and structural typing bypass.
- When changing routeMessage from async to sync, remember to rebuild `@actor-kit/worker` before typechecking `@actor-kit/test` — the test package resolves imports from the built dist, not source.
- To infer Zod payload types without importing `z`, use `{ schema: { _output: infer P } }`. Zod types have `_output` property (used by `z.infer` internally). This avoids adding `zod` as a direct dependency to packages that only need type-level inference.
- When extracting roleNames for binary frame decoding, always use `Object.keys(def.roles)` — NOT `Object.keys(def.views)`. The worker encodes roleIndex from `Object.keys(def.roles)`. Mismatched key sources produce wrong role mappings.
- For per-role binary view schemas, track the `activeSchema` from the last SNAPSHOT frame. DELTA frames don't carry roleIndex, so delta decoding must use the schema established by the preceding snapshot.
- When adding overloads to distinguish contract vs viewSchema, the contract has `{ name, def }` while SchemaDefinition has `{ kind: "schema", shape, fields }`. TypeScript resolves the correct overload based on these structural differences.
- When inferring Zod types for public API parameters that go through `safeParse()`, use `_input` (not `_output`). `_output` is the post-transform type; `_input` is what the caller actually passes. For `z.coerce.number()`, `_input` is `unknown` while `_output` is `number` — using `_output` would reject valid raw inputs at compile time.
- When adding a contract overload to an existing function, constrain the overload to require all properties the implementation needs (not just `{ name, def }`). `defineActor()` only requires `input`/`init`, so a contract without `roles`/`messages`/`views` would type-check but crash at runtime.
- After changing test-related package source (packages/test/src), always rebuild (`pnpm build`) before running tests — vitest resolves `@actor-kit/test` from dist/.
- When deriving DO binding names from contract names, replace hyphens with underscores after uppercasing: `"my-actor".toUpperCase().replace(/-/g, "_")` → `"MY_ACTOR"`. Cloudflare wrangler bindings use UPPER_SNAKE_CASE, but contract names use kebab-case (e.g., `counter-v3` → `COUNTER_V3`). Without the replace, `"COUNTER-V3"` won't match the env binding.
- When converting role-nested messages to flat messages with guards, the error code changes from `"message_not_found"` to `"guard_failed"` for role-restricted messages. Update all test assertions and WebSocket error frame expectations accordingly.
- When writing new files for integration tests, always run `biome check --fix` before committing. New files may not match the formatter's indent/spacing defaults, causing a format error that blocks the pre-commit hook.
- `defineActor()` contracts support `after`, `tick`, `lifecycle`, `initial`, `states` — all are passed through to `actor()` via `createActorClass`. The only constraint on `defineActor` is `{ input: ZodType; init(...args): unknown }`. Additional properties are unconstrained and preserved as-is. This means after/tick handlers CAN use typed state params (no `as` casts needed) since defineActor doesn't constrain them.
- When adding a new message to a test actor for guard coverage, ensure ALL state fields are updated consistently. The codex review caught `GUARDED_ADD` not updating `lastCaller`, which would make snapshots stale for consumers relying on that field.
- `new Request(request)` (copy constructor) transfers the body stream from the original, marking `original.bodyUsed = true`. This is standard fetch spec behavior — not a bug. For the Worker→DO forwarding pattern, the original is never reused, so this is fine. Avoid `new Request(url, { body: request.body })` which requires the `duplex: "half"` option (not in TS types, requires `as` cast).
- When adding new exports to `@actor-kit/worker` entry points, biome requires exports to be sorted by module path. Run `biome check --fix` after adding new export lines to avoid import-ordering lint errors that block the pre-commit hook.
- When adding header-based auth to a DO fetch handler, remember the header-spoofing risk: if a Worker forwards raw client requests via `stub.fetch(request)`, the client can set identity headers. withCallerIdentity scrubs headers before stamping, but only if the Worker calls it. Defense-in-depth: Origin validation (task 8) prevents browser-based CSRF.
- JWT-based WebSocket auth tests (`vitest-pool-workers` non-isolated mode) have a pre-existing failure: `getCallerFromToken` throws inside the DO's `fetch()` even though it works when called directly in test code. Likely a miniflare/vitest-pool-workers crypto context issue with the `jose` library inside DOs. Does NOT affect header-based auth tests.
- When the DO fetch handler response for WebSocket upgrade doesn't use a subprotocol, omit the `Sec-WebSocket-Protocol` response header entirely. Sending an empty or undefined value breaks the WebSocket spec handshake.
- When adding a new subpath export to `@actor-kit/worker` (e.g., `./token`), always add a matching alias in `vitest.config.ts` so unit tests resolve to source, not `dist/`. Without the alias, `pnpm test:unit` on a clean checkout (no `dist/`) will fail. The alias order matters: subpath exports must come before their parent package alias.
- Replacing `/api/token` with query param-based identity in examples does NOT change the security posture — the old flow also had an unauthenticated endpoint (`/api/token?callerId=anyone`) that minted JWTs for arbitrary callers. The real auth boundary is the Worker's own authentication (session cookies, OAuth), not the token endpoint. Origin validation (Task 8) is the defense against WebSocket CSRF.
- Origin validation for WebSocket CSRF must NOT reject requests with absent Origin header — non-browser clients (Worker-to-DO, Node) don't send Origin. Browsers always send Origin on WebSocket upgrades, so presence/absence distinguishes browser from non-browser. Check `origin && !allowedOrigins.includes(origin)` not `!origin || ...`.
- When tracking which auth path was used in the DO fetch handler (header-based vs token), use a boolean flag (`usedHeaderAuth`) rather than checking `tokenProtocol` — when both headers and token subprotocol are present, headers win (priority 1) but `tokenProtocol` is still truthy. The flag correctly reflects the actual auth method used.
- Durable Object migrations in wrangler.toml are append-only. Never add a new class to an existing migration tag — persisted environments that already applied that tag won't re-apply it. Always create a new migration tag (e.g., `v2`) for new DO classes.
